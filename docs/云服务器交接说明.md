## 2. 怎么进来

### 2.1 已有免密密钥的机器

```bash
ssh <DEPLOY_USER>@<SERVER_IP>
```

已授权的公钥记录在服务器 `/home/<DEPLOY_USER>/.ssh/authorized_keys`，可直接登录。
私钥只保存在维护者本机，不随仓库分发。

### 2.2 给另一台机器 / 另一个 agent 加权限

在**对方机器**上生成密钥后，把公钥追加到服务器（推荐用独立账号，见 2.3）：

```bash
# 对方机器：生成
ssh-keygen -t ed25519 -C "other-agent"
# 本机代传（或对方自己 ssh-copy-id）
scp other-agent.pub <DEPLOY_USER>@<SERVER_IP>:/tmp/
ssh <DEPLOY_USER>@<SERVER_IP> 'mkdir -p ~/.ssh && cat /tmp/other-agent.pub >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys'
```

### 2.3 建议：给其他 agent 单独开账号（不要都给 root）

```bash
ssh root@<SERVER_IP>   # 仅首次开账号时用 root，之后一律走 deployer
useradd -m -s /bin/bash deployer
mkdir -p /home/deployer/.ssh && chmod 700 /home/deployer/.ssh
# 把对方公钥写入 /home/deployer/.ssh/authorized_keys 并 chmod 600
# 授权改代码 + 重启服务（最小集）：
cat >/etc/sudoers.d/deployer <<'EOF'
deployer ALL=(root) NOPASSWD: /usr/bin/systemctl restart lawanswer-api, /usr/bin/systemctl status lawanswer-api, /usr/bin/systemctl reload nginx
EOF
chmod 440 /etc/sudoers.d/deployer
# 让 deployer 能读写项目（注意：不要 chown 整个目录，见第 9 节）
usermod -aG lawanswer deployer
chmod -R g+w /opt/lawanswer/app /opt/lawanswer/config.py
```

### 2.4 SSH 安全基线（每一项都当待办逐条勾）

- 安全组把 22 端口收敛到固定出口 IP，不对全网开放；
- `PermitRootLogin no` + `PasswordAuthentication no`，只允许密钥登录；
- 日常操作使用非 root 账号（见 2.3），root 仅用于紧急恢复；
- 主机内不要额外暴露管理面板（宝塔类面板的默认端口扫描命中率极高，见第 3 节）。

> 云安全组是唯一防线时，它的规则就等同于整套系统的认证边界——不要在这条链上留任何默认值。

## 5. 配置：两个 `.env`，职责完全不同

| 文件 | 权限 | 内容 | 谁读 |
|---|---|---|---|
| `/etc/lawanswer/lawanswer.env` | `640 root:lawanswer` | **应用全部配置 + LLM 密钥**（90 个变量） | systemd `EnvironmentFile` 注入 |
| `/opt/lawanswer/.env` | `600` | **只放 compose 需要的密码**（`MYSQL_ROOT_PASSWORD` 等，269 字节） | `docker compose` |

> ⚠️ **绝不能**把 `LLM_API_KEY`、`DASHSCOPE_API_KEY`、`JWT_SECRET` 写进项目根 `.env`。
> 启动自检 `assert_secrets_not_in_dotenv` 会直接拒绝启动（这是设计约束，不是 bug）。
> 也不要创建项目根 `.env` 的其他副本。

关键只读参数（当前生效值）：

```
APP_ENV=prod                      SERVER_HOST=127.0.0.1   SERVER_PORT=8101
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_DEFAULT_MODEL=deepseek-v4.1-flash   LLM_THINKING=disabled
EMBEDDING_PROVIDER=bm25           RERANKER_PROVIDER=none
MILVUS_LOCAL_PATH=/opt/lawanswer/volumes/milvus-lite/lawanswer.db
MILVUS_COLLECTION=law_chunks      MYSQL_PORT=3307  REDIS_PORT=6380  REDIS_DB=3
CORS_ORIGINS=https://<YOUR_DOMAIN>
CACHE_QA_TTL=604800  CACHE_ANSWER_ENABLED=true  CACHE_ANSWER_TTL=604800
TRUST_PROXY=true  TRUSTED_PROXIES=127.0.0.1,::1  CAPTCHA_FAIL_OPEN=false
```

改配置后**必须** `systemctl restart lawanswer-api` 才生效（无热加载）。

## 8. 改代码上线的标准流程

### 8.1 后端（Python）

```bash
# 1) 先备份要改的文件（必须有，服务器没 git）
cd /opt/lawanswer && mkdir -p .bak-$(date +%m%d-%H%M) && cp config.py .bak-*/  # 按需

# 2) 改代码（本地改好后 scp，或直接在服务器上 edit）
#    属主必须是 lawanswer，否则 systemd 里的进程读不到/写不了
chown lawanswer:lawanswer <改过的文件>

# 3) 冒烟：先确认能 import，再重启（避免重启后起不来）
/usr/local/bin/lawanswer-python -c "import app.main"

# 4) 重启 + 等就绪
systemctl restart lawanswer-api
for i in $(seq 1 25); do sleep 1; curl -sf -m 2 http://127.0.0.1:8101/api/health >/dev/null && echo "ready ${i}s" && break; done

# 5) 验证：health + 一次真实问答（见 8.3）
```

新增配置项的顺序**不能颠倒**：先写 `/etc/lawanswer/lawanswer.env`，再上传代码。
反了会因为代码里 `Field(...)` 必填而启动失败。

### 8.2 前端（Vue）

服务器**没有 node**，必须本地构建后上传：

```bash
# 本地
cd frontend && npm run build
scp -r dist/* <DEPLOY_USER>@<SERVER_IP>:/opt/lawanswer/frontend/dist/

# 服务器：Nginx 直接读 dist，无需 reload（内容变了就行）
ls -l /opt/lawanswer/frontend/dist/index.html
```

升级前建议 `mv dist dist.prev-$(date +%H%M%S)` 留回滚点。

### 8.3 端到端验证（SSE，脚本在服务器 /tmp）

```bash
/usr/local/bin/lawanswer-python /tmp/check_stream_cache.py     # 缓存命中验证
```

或手写一次：注意 `POST /api/chat/stream` 的字段名是 **`query`**，不是 `question`；
带 `session_id` 时必须登录（`Authorization: Bearer <JWT>`）。

## 9. 绝不能做的 5 件事（都是真实踩过的坑）

1. **不要 `chown -R lawanswer:lawanswer /opt/lawanswer`**
   `volumes/` 会被一起改掉 → Redis 容器内进程 uid=999 写不了 `dump.rdb` → `stop-writes-on-bgsave-error`
   生效 → **全量写命令被禁** → 验证码写不进 Redis → 登录/注册全挂（曾经的真实 P0）。
   正确写法：
   ```bash
   find /opt/lawanswer -maxdepth 1 -mindepth 1 ! -name volumes -exec chown -R lawanswer:lawanswer {} +
   ```
2. **不要 `docker compose up -d` 拉全栈**
   compose 里定义了 milvus/etcd/minio，但**故意没启动**：Milvus standalone 常驻 2.0–2.5 GB，
   而机器总共 1.6 GB。启动会 OOM，把 MySQL/Redis 一起拖死。
   只起需要的：`docker compose up -d mysql redis`。
3. **不要把密钥写进项目根 `.env`**（见第 5 节，启动自检会拒绝）。
4. **不要用 `systemctl restart nginx` / `is-active nginx` 判断 Nginx 状态**（宝塔环境，用 `/etc/init.d/nginx`）。
5. **不要用 `env $(grep -v '^#' file | xargs)` 注入环境变量**（值里有空格/特殊字符会炸）。
   统一用 `/usr/local/bin/lawanswer-python`（它内部 `set -a; . /etc/lawanswer/lawanswer.env`）。

## 10. 已知限制（不是故障，别当 bug 修）

| 现象 | 原因 | 影响 / 处置 |
|---|---|---|
| `docker ps` 里没有 milvus / etcd / minio | 用 `milvus-lite` 本地文件模式（`MILVUS_LOCAL_PATH`），不需要独立服务 | 正常。collection 在 `volumes/milvus-lite/lawanswer.db` |
| `EMBEDDING_PROVIDER=bm25` | 百炼 embedding 额度耗尽（403 `AllocationQuota.FreeTierOnly`），且 1.6G 内存装不下 bge-m3（2.3G） | 只有关键词能力，无语义泛化（"赔钱"匹配不到"经济补偿"）。要恢复语义检索：修额度或接硅基流动 bge-m3，**切回后必须重建 collection** |
| `RERANKER_PROVIDER=none` | 同上，reranker 也要 2.3G | 重排质量下降，靠 RRF + 法域过滤兜底 |
| bm25 模式下余弦相似度恒为 `None` | `Bm25Embedder.encode()` 的 dense 是固定 1024 维零向量 | 已用「字面双门」兜底（`QA_TEXT_GATE_*`）；新增依赖余弦的逻辑必须留非稠密分支 |
| HTTPS 证书 | 手动证书在 `/etc/lawanswer/ssl/`，**certbot 未安装、无自动续期** | 到期 2027-01-25，到期前必须手动换证书，否则全站 HTTPS 失效 |
| 内存余量小 | 总 1.6G，常驻约 1.3G，可用 350M，swap 1G | 别在这台机器上跑训练/大模型；`docker stats` 看谁在涨 |
| 无 git | 服务器没装 git | 每次改动前手工备份；建议 `yum install -y git` 后建 bare 仓库或用 rsync 快照 |
| 未备案 | 域名 http 访问 403（阿里云拦截） | https 正常。这是唯一阻塞项，无法从服务器侧绕过 |
