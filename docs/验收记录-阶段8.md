## 4. 本阶段发现并修复的问题

### 4.1 `uv sync` 会把 GPU 版 torch 换回 CPU 版（阻断性问题）

- **现象**：`uv sync` 卸载 `torch 2.14.1+cu130` 并尝试装 CPU 版；因运行中的服务占用 `.pyd` 文件，
  报 `os error 5 拒绝访问`，装也装不上 —— 结果是 GPU 环境被破坏且装不回来。
- **根因**：`pyproject.toml` 里 `torch>=2.14.1` 解析成 CPU 版，与手工安装的 `+cu130` 本地版本段不一致。
- **修复**：
  1. `bootstrap.ps1` 检测到 `.env` 为 cuda 且已装 `+cu` 版时，自动加 `--no-install-package torch`；
  2. 后续所有 `uv run` 加 `--no-sync`（`uv run` 默认会先自动 sync，同样会覆盖）；
  3. 启动后端子进程也带上同一保护参数；
  4. `pyproject.toml` 与 README 常见问题都写明这条坑与正确命令。
- **验证**：连跑三次 bootstrap，torch 始终为 `2.14.1+cu130` 且 `cuda=True`。

### 4.2 两个单测在本机失败（非新代码引入，是环境/遗留断言）

| 用例 | 原因 | 修复 |
|---|---|---|
| `test_retrieval.py::test_default_ranker_is_weighted_dense_first` | 断言默认加权，但消融已证伪并回退为等权 RRF | 改为显式用 `settings_factory` 构造，拆成 rrf / weighted 两条用例，不再依赖本机 `.env` |
| `test_orchestration_service.py::test_no_key_still_works` | 本机新配了 `DEEPSEEK_API_KEY`，用例本意"无密钥走规则兜底"失效，**还真的调了线上 LLM（1.6s）** | 用 `monkeypatch.delenv` 清掉三个密钥变量，恢复"全离线"承诺 |

### 4.3 清理遗留死配置

`RetrievalConfig.ranker`（默认 `"weighted"`）与顶层 `retrieval_ranker`（默认 `"rrf"`）并存且前者从未被使用，
两者默认值还互相矛盾。已删除死字段与其构造传参。

### 4.4 控制台中文乱码

PowerShell 5.1 默认按 GBK 解码子进程 stdout，导致 `uv run python` 输出的中文全成乱码。
脚本开头统一设置 `[Console]::OutputEncoding` / `$OutputEncoding` / `PYTHONIOENCODING=utf-8` 后正常。
