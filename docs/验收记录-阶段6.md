## 二、本阶段范围调整（需知悉）

前端 6 页依赖登录与会话接口，而 **auth / sessions 两组 API 不在原八阶段清单**（阶段 5 汇报时已提示）。本阶段按"前端所需"补齐，
并顺带补了 ULID、验证码、JWT 鉴权与登录失败锁定。

| 文件 | 职责 |
|---|---|
| `app/core/ids.py` | ULID（26 位 Crockford Base32，时间有序，会话列表天然有序） |
| `app/core/security.py` | bcrypt(cost=12)、JWT 签发/解析、`get_current_user` / `..._optional` 依赖、账号密码规则 |
| `app/core/captcha.py` | 4 位数字 **SVG** 验证码（干扰线+噪点+字符抖动）、Redis 一次性校验、Redis 故障降级放行 |
| `app/api/auth.py` | 验证码 / 注册 / 登录 / me / 实时查重；失败 5 次锁 60s |
| `app/api/sessions.py` | 会话 CRUD（软删）+ 消息历史；**全部按 user_id 隔离**，他人会话 404 |

修改：`app/api/chat.py`（会话模式必须登录且会话归属当前用户）、`app/main.py`（注册路由）、
`config.py`（`CAPTCHA_TTL_S` / `LOGIN_FAIL_LIMIT` / `LOGIN_FAIL_WINDOW_S`）、`.env`、`app/core/errors.py`（`RateLimited`）。

## 五、走查发现并修复的 3 个真实缺陷（都不在本阶段"新写代码"里）

| # | 症状 | 根因 | 修复 |
|---|---|---|---|
| 1 | 上传文档在列表里显示成 `<随机ID>_原名.md`，解析页进度永远匹配不上 | `ingest()` 用 `prepared.source_file`（磁盘存储名）回写 `documents.filename` 与 `storage_path`，覆盖了上传时的原名，还把路径改成 `data/raw/` | 新增 `get_document_naming()`，入库时沿用库内已有 filename/storage_path（`app/ingest/pipeline.py`） |
| 2 | 同一文件传两次变两条文档，"内容未变跳过"完全失效 | `upsert_document` 的 `ON DUPLICATE KEY UPDATE` 漏了 `content_sha1`，pending 行的 40 位占位哈希永不被真实 SHA1 覆盖 | 补 `content_sha1 = VALUES(content_sha1)`；占位哈希改为每次唯一（否则同库第二条 pending 直接撞 `uk_kb_content`） |
| 3 | 点"重新解析"报 500 | `reingest` 里 `dict(parse_config)`，而 MySQL JSON 列经驱动读回是**字符串** → `dict("{...}")` 抛 ValueError | 先 `json.loads` 再 `dict()`（`app/api/knowledge.py`） |

三者都有回归用例：`tests/test_upload_flow_integration.py`（2 个联调用例：展示名/存储路径保持、重复上传不留幽灵行）。

另：走查还暴露了**重复上传留下永久"排队中"占位行**的问题，已在跳过分支中清理（同文件内覆盖）。
